# Mission: Becoming AI-Forward — Build, Architect & Secure AI-Native Systems

## Why
I'm a senior engineer with strong security instincts, but new to AI. I want to reach the point
where I can design, ship, and defend a production-grade AI-native system myself — and be the
person on a team who makes sound, security-aware calls about where and how AI belongs.

## Success looks like
- I can **build** a reliable AI-native feature: model calls, tool use, RAG, an agent loop, and
  evals that tell me it actually works.
- I can **architect** an AI system with defensible trade-offs (when *not* to use AI, patterns,
  memory, cost/latency/reliability, observability) — captured in a real design doc / ADR.
- I can **secure** LLM/agent systems: threat-model them, red-team for prompt injection and
  agentic abuse, and harden a system I built.
- I finish a **capstone** that integrates all three. The *target is still open* — hardening the
  AI angle of my own security-scanning repo is one candidate, not a commitment. We'll choose it
  deliberately as skills develop (see NOTES "Still open").

## Constraints
- ~5 hrs/week, moderate/steady cadence (bursty weeks happen — lessons must be resumable).
- Learn **concept-then-practice**: mental model first, then a hands-on win.
- Security should be **woven through every lesson**, not saved for the end — it's my strength.
- Senior SWE fundamentals are solid; assume no prior LLM/AI knowledge.

## Out of scope (for now)
- Training/pre-training internals and heavy ML math (I need working mental models, not to build
  transformers from scratch).
- Non-LLM ML (classical ML, CV pipelines, etc.) except where it informs an architecture call.
- Chasing the leaderboard — I care about durable skills, not this month's model rankings.
