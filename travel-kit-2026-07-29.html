L01 · foundation

A model call has one root property and three consequences. Name the root property, the three consequences, and the course discipline each one forces.

tap to reveal · think in a 3-row table first
Root property: a model call is a stateless, one-shot, sampled next-token predictor. The three consequences → disciplines: Stateless (forgets between calls) → Memory / RAG; One string (instructions + data arrive fused, unseparable) → Security / injection; Sampled (probabilistic output) → Evals. Trap you've hit before: hallucination is a symptom of “Sampled,” not a fourth consequence.
L02 · foundation

The model forgets everything between turns. So how does a chatbot “remember” the conversation — and why is that mechanism the engine of prompt injection?

tap to reveal · the answer is about what the app does, not the model
The app resends the entire transcript on every turn — the model doesn't remember, your code re-feeds it. So injected text isn't a one-shot: once it's in the transcript it persists and compounds, replayed into every future turn. And roles (system/user) are a learned prior, not a boundary — a trained tendency the attacker can argue the model out of.
L07 · evals due 07-31

On a red-team gate: what's the attacker's success metric vs. the defender's? And what does a run where the attack simply doesn't fire prove?

tap to reveal · two metrics, one trap
Attacker = pass@k: needs ≥1 success in k tries (one win is a breach). Defender = pass^k: the gate must hold on every fired run. A non-firing run proves nothing — the model just happened not to comply that time (a coin flip). Credit goes only to the code gate on runs where the attack actually fired.
L07b · scorecard due today

Your triage scorecard comes back F2 = 1.00. Why is a perfect score a yellow flag, not a green one — and why F2 (β>1) rather than plain accuracy?

tap to reveal · a perfect eval has a specific defect
A 100% eval has no teeth: it detects no regression (same family as the false-green trap) — it means the test set is too easy and lacks boundary + adversarial cases. The perfect score was the probabilistic layer holding on one easy phrasing (pass@k — the attacker only needs one miss), not a wall. You bias recall (F2, β>1) because a false negative = a shipped exploit; a false positive only costs review time.
L07c · least privilege due today

A blocklist tripwire caught every injection in your battery (I1–I5), 100%. You rejected it anyway. Why — and what's the robust fix?

tap to reveal · you drove this insight yourself
Reject it: a blocklist needs n + ∞ markers (unwinnable — novel phrasing I6 walks right past it), and the 100% was circular — the markers were fit to the test (teaching to the test). Robust fix = least privilege on the decision: the agent may RAISE / NEEDS_REVIEW but never DISMISS. Remove the dangerous verb entirely → “0 shipped” becomes structural and phrasing-independent, not a filter you have to keep patching.
L07c · CI gate due today

Your security CI gate runs with no API key — no secret, no network, no flake. How is that possible, and why is it the whole point?

tap to reveal · what is the test actually testing?
It tests the deterministic invariant, not the model. You stub the model to its worst case — fully compromised, every finding → “not exploitable” — and assert 0 exploits still ship. Because the guarantee lives in code (triage_core.py, the single source of truth), the test needs no key, no network, no live call. That's “gate on code, not the model” made literal. Any regression that reintroduces a dismiss/close verb fails the build.
Capstone · the review queue

The fail-safe routes low-confidence findings to a junior human. Name the trap hiding in that design, and the two guardrails that keep “0 shipped” true in practice.

tap to reveal · this is your newest Architect call
Trap: the queue is adversarially enriched — the injected/manipulated cases (like I6) land in NEEDS_REVIEW, so the hardest, most attacker-shaped decisions go to the least experienced human. And an over-shrunk or over-full queue → rubber-stamping → NEEDS_REVIEW silently decays back into DISMISSED. Guardrails: (1) govern absolute throughput (findings ÷ reviewer ÷ time), not the ratio — 40% is humane at 10 findings, drowning at 1000; (2) agent #1 must arm the reviewer: code location, data-flow, a suggested exploit path, plus an escalation lane to a senior. The output is never a bare label — it's label + evidence + confidence + escalation path.

The Context-Window Perspective on LLMs — memory and reasoning seen through the finite context window. ~10 min, reads fine on a phone.

Hold this question while you read

Memory is just more untrusted context, injected at a different point in the loop — and it's worse than a one-shot injection. Ask yourself: if agent #1 stores prior findings so it can dedupe across scans, why does a poisoned memory outrank a poisoned tool result? (Hint: a poisoned tool result burns one run; a poisoned memory replays every session.) And: does “memory” change where the authority to close a finding lives? It must not.
